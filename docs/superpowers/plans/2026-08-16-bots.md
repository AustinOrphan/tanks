## PR 2a — Bots: mechanism only, no competence change

**Scope, unchanged from the source design.** `createBotInputSource` generalizes the
substitution `loop.ts`'s `autoplay` flag already performs at slot 0 only
(`effectiveInput.sample()`'s per-slot map), to `bots=K` filling the LAST K of the N
player slots, with each bot's own `PlayerAiState` and RNG stream derived from the
world's own resolved seed rather than `wallMs()`. `decidePlayerInput` itself is
untouched -- competence work is PR 2b/2c. **No `src/sim/` file was edited**; `git diff
--stat` against `origin/main` touches exactly `src/game/devflags.ts`,
`src/game/devflags.test.ts`, `docs/dev-flags.md`, `src/game/loop.ts` and
`src/game/loop.test.ts`.

**The RNG offset -- the source design's own draft collided, and this PR picked a
different, provably wider-collision-free construction instead of patching the literal.**
The n-player arc's PR2 draft proposed `mulberry32(seed + 1000 + slot)`. `1000` is also
`targeting.ts`'s own wander-stream multiplier (`wanderMove`: `nextRng(world.seed +
tank.id * 1000 + bucket)`), so the draft's slot-0 key (`world.seed + 1000 + 0`) is
LITERALLY the same integer `wanderMove` computes for an id-1 enemy's very first decision
(`tank.id = 1`, `bucket = 0`) -- a real, reachable, no-mutation-needed collision, not a
hypothetical one. Every per-tank enemy stream in `targeting.ts` (wander 1000, retreat
4243, mine inclination 6101, aim jitter 7919) shares the shape `world.seed + tank.id *
PRIME + bucket`, with `PRIME > 0`, `tank.id >= 1` (arena.ts's grid-scan id counter starts
at 1 and never assigns 0 to any tank) and `bucket >= 0`. So every reachable enemy key is
strictly GREATER than `world.seed`, for any positive prime -- not only today's four.
Adopted construction: `mulberry32(world.seed - BOT_SEED_SPACING + slot)`, subtracting a
fixed spacing (`BOT_SEED_SPACING = 1009`, > 3, the largest slot index bots can reach)
rather than adding one, so every bot key is strictly LESS than `world.seed`. The two
families are disjoint by construction -- not merely by avoiding four specific literals --
which also means PR 2c's planned fifth per-tank prime cannot collide with it either,
whatever value it picks, as long as it keeps the same additive-from-`world.seed` shape
every existing stream uses (named as a dependency in `BOT_SEED_SPACING`'s own doc
comment, in case a future prime ever goes negative relative to `world.seed`, which none
does today).

**Slot fill: LAST K of N, unchanged from the source design.** `botSlotsFor(playerCount,
botCount)` returns `{playerCount - botCount, ..., playerCount - 1}`. `botCount` is
`Math.min(devFlags.bots ?? 0, playerCount)` -- the two flags parse independently
(`devflags.ts` has no view of either's counterpart), so a combination like `bots=4` with
`players=2` clamps to claiming both slots rather than erroring on a 4th slot that does
not exist. `bots=K` may equal `playerCount`, including at the unflagged default of one
player, where `bots=1` puts a bot in the sole slot -- the fully autonomous match owner
directive 1 literally asks for ("simulate multiplayer using computer players").

**A bot-claimed slot never constructs its slot's real controller.** `realSources: Map<
number, PlayerInputSource>` replaces the old `slots` array: slot 0 (`input`, the
keyboard/mouse/touch controller) is always built -- other wiring depends on it regardless
(`screenToGround`, the touch indicator, the mute/pause hotkeys) -- but slot 1's gamepad
reader and slots 2+'s idle sources are each gated on `!botSlots.has(i)`, so a bot-claimed
slot 1 never calls `deps.createGamepadSource()` at all (proven the same way the couch-
coop PR already proves slot 1's construction: the `gamepadSourceBuilds` spy count, 0 when
slot 1 is bot-claimed vs. 1 when it is not). Idle-slot construction has no equivalent
factory seam in `GameDeps` (unlike slot 1's gamepad source, `createIdleInputSource` is a
plain module function loop.ts calls directly, not injected) -- extending `GameDeps` with
one was judged out of this PR's scope (the source design's own file list is `loop.ts`/
`devflags.ts` only). A bot-claimed idle slot is instead proven BEHAVIORALLY: unlike an
idle source (whose `move` is the literal `{0,0}`, so the tank never leaves spawn),
`decidePlayerInput`'s move is `avoid ?? seekLikeMove(...)`, and `seekLikeMove` never
returns the zero vector (it falls back to a wander heading) -- so a bot-claimed slot's
tank measurably leaves its spawn position over many ticks in a real multiplayer world
with live enemies, which a naive idle-source regression could not produce. This is a
narrower proof than the construction-count spy gives for slot 1, named here rather than
overstated as equivalent.

**Precedence when both `autoplay` and `bots` claim slot 0 -- a source-design gap, closed
here.** The n-player arc's PR2 section did not address this interaction (`bots=K` can
reach slot 0; `autoplay` only ever targets slot 0). Adopted: `autoplay` is checked first
in `effectiveInput.sample()`'s per-slot loop, unchanged from today's sole branch, so it
wins. This is a deliberate, narrow exception to bots' own reproducibility guarantee:
autoplay's stream is seeded from `wallMs()`, so a session with BOTH flags set is not
reproducible at slot 0 even under a pinned `?dev=1&seed=`. Every other bot-claimed slot
is unaffected -- autoplay only ever substitutes slot 0.

**Sandbox -- a deliberate departure from `players`' own exclusion, not an oversight.**
`players` is excluded from the sandbox (`createSandboxWorld` takes no `playerCount`).
`bots` is NOT: the sandbox always resolves to a single slot (`playerCount` forced to 1
regardless of the flag), and `bots=1` there is exactly what `autoplay=1` already does
UNGUARDED today -- the sandbox's one player-kind tank driven by the scripted brain
instead of the input controller. Excluding `bots` from the sandbox to mirror `players`
would have been inconsistent with the arc's own framing of bots as "autoplay
generalized," so this PR does not add that exclusion. Documented in both
`devflags.ts`'s `bots` doc comment and its `FLAG_REGISTRY` entry.

**World-seed derivation.** `loop.ts`'s `nextSeed()` resolves to `deps.devFlags.seed ??
deriveSeed(deps.wallMs())`, and `buildWorld` threads that resolved value into
`deps.levels.world(...)`, landing on `World.seed`. Each bot's RNG stream and
`PlayerAiState` are built by `createBotSources(world.seed, botSlots)`, called once at
initial construction (against the boot world) and again inside `switchTo` (against every
later world) -- reseeded per WORLD, not per SESSION, unlike `autoplayRnd`/`autoplayState`
further down the same file. This is a deliberate asymmetry: autoplay is a demo aid with
no reproducibility contract; bots exist specifically to simulate a reproducible session
(`?dev=1&seed=42&bots=K` must replay identically), and a pinned dev seed resolves to the
SAME value on every level (`nextSeed` returns the constant unconditionally), so
per-world reseeding keeps every level's bot behaviour a pure function of that level's own
seed rather than of how much a previous level's stream had already consumed.

**File-level changes, matching the source design's own list exactly.** `src/game/loop.ts`
(`createBotInputSource`'s substitution folded into the existing per-slot map,
`createBotSources`/`botSlotsFor`, `BOT_SEED_SPACING`, `realSources` replacing the old
`slots` array, `tankForSlot` hoisted out of `onSimulated` so both it and the bot
substitution share one resolution), `src/game/devflags.ts` (`bots`, a valued flag, the
`asPlayers` idiom: 0 is an explicit no-op, 1-4 claim that many of the last slots, anything
else rejects to `null`). `docs/dev-flags.md` regenerated (`npm run devflags:doc`) --
the `FLAG_REGISTRY` completeness guard forces the registry entry, and the generated doc
must follow it in the same change. **No `src/sim/` changes.**

**Red-first plan -- three mutations, applied by hand against the finished
implementation, observed red, then reverted (not committed as `tools/mutate` entries: the
existing manifest gate was re-run afterward and still passes at 13/13, see Full gate
below).**

1. **Fill rule: last-K vs first-K.** `botSlotsFor`'s loop mutated from `for (let i =
   playerCount - botCount; i < playerCount; i++)` to `for (let i = 0; i < botCount;
   i++)`. Scoped run: `npx vitest run src/game/loop.test.ts` (244 tests, the full file --
   the pins for this claim live there). Result: **2 of 244 failed** -- the direct
   `botSlotsFor` unit assertion and the `bots=2` at `players=4` wiring test (whose
   discriminator is exactly `gamepadSourceBuilds`: 1 under last-K since slot 1 is
   untouched, 0 under the mutation since slot 1 would be claimed instead).
2. **RNG offset collision.** `BOT_SEED_SPACING` mutated from `1009` to `-1000`, which
   makes `world.seed - BOT_SEED_SPACING + slot` equal `world.seed + 1000 + slot` -- the
   source design's own rejected draft, reproduced exactly. Scoped run: same file.
   Result: **1 of 244 failed** -- the collision-freedom test (caught at its first
   `toBeLessThan(seed)` assertion, before it even reaches the exact-equality check
   further down the same test).
3. **Seed source: `world.seed` vs `wallMs()`.** The initial `createBotSources(world.seed,
   botSlots)` call mutated to `createBotSources(deps.wallMs(), botSlots)`. Scoped run:
   same file. Result: **1 of 244 failed** -- the reproducibility test, with a real,
   multi-tank, multi-field divergence in the printed diff (positions, `turretAngle` and
   `bodyAngle` all differed across several tanks), not a single coincidental field --
   confirming the mutation's effect was genuinely wired through, not a vacuous pass on a
   scenario where nothing moved either way.

All three were reverted and read back (`grep` against the restored literals) before
committing; `npx tsc --noEmit` and the full suite were re-run clean after each revert.

**The reproducibility test's shape.** Two full sessions built via the SAME test harness
(`makeDeps`/`boot`, `src/game/loop.test.ts`), both with `devFlags: { seed: 42, players:
3, bots: 3 }` (a fully autonomous 3-tank match, no `autoplay`) but DIFFERENT `wallMs`
(111 vs. 987654321) -- since `devFlags.seed` is set, `nextSeed()` ignores `wallMs()`
entirely for the world's own seed, so `wallMs` can only reach the trajectory through a
bot's RNG construction, making this both the reproducibility proof and (under mutation 3
above) the attribution proof for the same claim. Both sessions are driven through the
IDENTICAL sequence of nine `fireFrame(now)` calls, and after each call the full
`{id, pos, turretAngle, bodyAngle}` tuple for every tank in the live world (`h.rec.
renders.at(-1)!.curr.tanks`, not the frozen boot-time world) is snapshotted. The
assertion is `expect(a).toEqual(b)` over all nine snapshots, not merely the final one --
per the task's own requirement to compare trajectories, not just outcomes -- plus a
sanity check that at least one tank's position actually moved between the first and last
snapshot, so a vacuous "nothing moved in either session" could not masquerade as a pass.

**Trace argument.** Two independent reasons, stated separately rather than folded into
one: (1) BEHAVIORAL -- the trace's player tank is driven by the recorded input stream

`324aa9b5d369ec6abc61f73e8e454de67b5fbf365f4b0df2eedf2c01add33bb5`, matching the
